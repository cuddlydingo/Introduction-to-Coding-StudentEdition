## What you'll learn this week

- How to verify and **ship** a final build.
- How to write a meaningful **reflection**.
- How to prepare **speaking notes** for a demo and a paper talk.
- How to build a **portfolio README** in Markdown that links your best work.

## 1. Ship the final build

Shipping means releasing a version you are confident in. Before you submit, run a
final check — the same discipline from Week 17:

```text
[ ] Program runs start to finish with no crashes
[ ] Every menu choice works
[ ] Invalid input shows a clear message
[ ] Instructions explain how to run it (python yourgame.py)
[ ] Files are named clearly and committed to your quest branch
```

A shipped project is one someone else can download, run by following your
instructions, and enjoy without your help.

## 2. Reflect like a maker

A **reflection** captures what you learned so your future self can build on it. Be
specific and honest — name real moments, not vague praise. A strong reflection
answers three prompts:

```text
Strongest skill:   Functions — I can break a problem into small, named pieces.
Biggest challenge: Debugging — reading tracebacks calmly took practice.
Next goal:         Build a larger project with saved game state.
```

## 3. Prepare your talks

You will speak twice at the Showcase. Speaking notes (an outline, not a script to
read word-for-word) keep you calm and clear.

**Demo speaking notes (2-3 minutes):**

```text
Intro        -> what the game is, in one sentence
Key feature  -> show one thing you're proud of, live
Challenge    -> a bug or design problem you solved
Lesson       -> the biggest thing you learned
```

**Research-paper talk (3 minutes):** your written paper was submitted in Week 17;
now prepare notes that state your **thesis**, **2-3 key findings**, **why it
matters**, and **one source you trust**.

```text
Hook -> thesis -> 2 key findings -> why it matters -> one trusted source
```

## 4. Build a portfolio README (Markdown)

A **portfolio** collects your best work in one place. You will write it in
**Markdown** — the same formatting language used throughout this course. The
essentials:

```markdown
# My Maker's Portfolio

A collection of my best work from Introduction to Coding.

## Highlights
- [Week 9 Checkpoint Game](week09_p5_checkpoint_game.py) — my first full playable game.
- [Week 13 Search Comparison](week13_p3_compare_steps.py) — linear vs binary search.

## What I learned
One or two sentences about your growth as a coder.
```

Markdown basics you will use:

- `#`, `##` for headings (bigger to smaller).
- `- item` for bullet lists.
- `[link text](path-or-url)` for links to your files.
- Backticks `` `code` `` for inline code.

Link at least five artifacts, each with a one-sentence note on why it matters.

## Common mistakes to avoid

- **Shipping without a final run-through:** always play it end to end first.
- **Vague reflections:** "I learned a lot" says nothing; name a specific skill and
  moment.
- **Reading slides word-for-word:** use notes and talk *to* your audience.
- **Broken portfolio links:** check that each Markdown link actually points to the
  right file.
